# Python-порт S-019 v0.4.9

Файл стратегии: `strategies/s019_v0_4_9.py`.
Исходник сохранён без изменений в `strategies/source/S-019_v0.4.9.mq5`.
SHA256 исходника:
`3091340e659e3c0165d045a4a76866141f98a3bf76687f1e6db09a1f848cbfd7`.

Это порт торгового ядра предоставленного файла, с явными границами соответствия.
Проведена ограниченная сверка с отчётом MT5 и доступными живыми логами;
полная идентичность советнику не подтверждена. Внешние include-файлы
не предоставлены; для реальных прогонов использовалась явно заданная
спецификация DAX40. Для запуска нужен backtester 0.4.0 или новее: прежний режим
целевого веса long/flat не может выразить сделки этого советника.

## Перенесённые правила

| MQL5 | Python-поведение |
| --- | --- |
| `CalculateLevels` | ADR по N завершённым рабочим барам, предыдущий Close, уровни 0.55/0.75 ADR по умолчанию, стоп за минимумом/максимумом окна |
| `OnTick`, новый рабочий бар | Строгое закрытие за **старыми** уровнями; затем пересчёт ADR и стопа с учётом сигнального бара |
| `SlowEMAAllowsEntry` | Long только выше Slow EMA, short ниже; `InpAllowCounterTrend` отключает фильтр |
| `ProcessClosedBarSignal` | Встречная позиция закрывается до проверки фильтра нового входа; пирамидинг не выполняется |
| `PlaceLimitOrder` | Вход на доле расстояния от стопа к сигнальному Close; при N=0.40 это 40% от стопа |
| `OpenMarketPosition` | При N=1 вход рыночным запросом на доступной текущей котировке |
| `BrokerValidStop`, `StopForPendingEntry` | Учет tick size, point, stops level, направленное округление SL |
| `BrokerValidTakeProfit`, `TakeProfitForPendingEntry` | TP от риска по RR, поправка на минимальную дистанцию, направленное округление |
| `CalculateVolumeByRisk`, `NormalizeVolumeDown` | Денежный риск / убыток одного лота до SL; округление лота вниз, min/max/step |
| `DeleteExpiredPendingOrders` | Срок лимитного ордера в реально наблюдавшихся рабочих барах; календарные пропуски не создают бары |
| `EnforceDailyPositionLimit` | Лимит фактически открытых позиций по серверному дню; выставление pending не занимает слот |
| `QueueEntry`, `ProcessPendingEntry` | Снимок Close/SL, задержка, отмена при новом сигнале, отсутствие повторной проверки пробоя после задержки |
| `ManageFridayClose` | Закрытие позиции, снятие pending и задержки с пятничного cutoff до понедельника; реализация по описанию основного файла |

Названия `Inp...` и их значения по умолчанию сохранены. Тест отдельно сверяет
все объявленные в основном MQL-файле input-параметры с Python-моделью.
Fast EMA, ADX и ATR в предоставленном коде используются только для отображения;
в дополнительные торговые фильтры они не превращались.

## Бары для сигналов, тики для исполнения

Советник использует рабочий таймфрейм, по умолчанию D1. Python строит его OHLC
из уже наблюдавшихся Bid-тиков, с границами по часовому поясу сервера брокера.
Пустые интервалы и выходные без котировок не заполняются искусственно.
Открытый бар не используется вместо завершённого при проверке сигнала.

Вся симуляция исполнения остаётся тиковой: pending, SL, TP, equity и управление
позицией проверяются на каждом исходном Bid/Ask. Архив исходных тиков не
заменяется дневными барами.

Slow EMA инициализируется первым наблюдённым закрытием, затем применяется
EMA с коэффициентом 2/(period+1). До накопления периода фильтр не разрешает вход.
MT5 может иметь более раннюю историю до начала теста: для сравнения нужно
подать соответствующий прогрев. Первый наблюдаемый бар также может быть неполным,
если исходный экспорт начинается посреди сессии. Короткий фрагмент из 11 тиков
не содержит истории для ADR3/EMA50 и не подходит для проверки результатов C19.

Поддерживаются фиксированные рабочие M/H-таймфреймы MT5 и D1. Для
`PERIOD_CURRENT` требуется `chart_timeframe`. W1 и MN1 не реализованы.

## Спецификация контракта обязательна

Параметр `broker` содержит:

- `symbol`, `account_currency`, `server_timezone`;
- `point`, `tick_size`, `digits`;
- `tick_value_per_lot` — стоимость одного tick_size за один лот **в валюте счёта**;
- `volume_min`, `volume_max`, `volume_step`;
- при необходимости `stops_level_points`, `freeze_level_points`;
- при наличии `margin_per_lot`, `commission_per_lot`.

Эти величины не выводятся из названия инструмента или цены. Предоставленная
спецификация DAX40 сохранена в активном профиле; её нельзя автоматически
считать спецификацией DE40 у другого брокера.
`examples/s019-demo-params.json` — искусственная спецификация
TEST_LINEAR_CONTRACT для проверки кода, не настройка реального NASDAQ/DAX/FX.
Имя контракта должно совпасть с symbol импортированного набора: случайное
применение параметров другого инструмента отклоняется.

Расчёт прибыли реализован для линейного контракта с постоянной стоимостью тика:

```text
PnL = direction × (exit − entry) / tick_size × tick_value_per_lot × lots
```

Вход в CFD-позицию не списывает её полную номинальную стоимость. `cash` в таком
отчёте означает реализованный баланс счёта; `quantity` — лоты со знаком.
Long переоценивается по Bid, short по Ask. При указанном margin_per_lot вход
проверяет доступность маржи, но margin-call/stop-out не моделируется.
Если поле отсутствует, проверка маржи не выполняется и это отражается в отчёте.

`InpRiskMoney` задаёт расчётный риск до SL без комиссий. Гэп и проскальзывание
могут увеличить фактический убыток, как и при реальном стопе. Валютная конвертация,
переменная стоимость тика и свопы не реализованы. Для таких инструментов текущая
линейная модель не является заменой MT5 `OrderCalcProfit`.

## Новости и отсутствующие зависимости

В основном файле есть include:

- `../Include/EaEventLog.mqh`;
- `../Include/NewsManager.mqh`;
- `../Include/CommonFridayClose.mqh`.

Их содержимое не предоставлено. Правила новостного окна, настройки по умолчанию,
получение календаря, удаление и восстановление TP нельзя восстановить полностью
из вызовов в основном файле. Поэтому по умолчанию фабрика останавливается с
понятной ошибкой. Вариант без новостного фильтра запускается только при явном
`"news_mode": "disabled"`; этот выбор и ограничения записываются в отчёт.
Он не выдаётся за полную копию советника с новостной защитой.

Для полного переноса нужно предоставить эти include-файлы, а для исторической
проверки новостей — соответствующие календарные данные. Пятничное окно сейчас
следует комментарию основного файла «до следующей недели»; его точные границы
ещё нужно сверить с CommonFridayClose.mqh.

## Запуск

Создайте собственный JSON параметров с реальным `broker`, нужными Inp-параметрами
и явной настройкой доступного новостного режима. Параметры можно передать файлом:

```sh
uv sync --frozen
uv run --frozen backtester run \
  --data data/YOUR_TICK_DATASET \
  --strategy strategies/s019_v0_4_9.py \
  --params @parameters/s019.json \
  --output results/s019-run-001
```

Все имена `Inp...` остаются такими же, как в MQL, например
`InpWorkingTimeframe`, `InpRiskMoney`, `InpEntryDelaySeed`. Неизвестные параметры
отклоняются. История до выбранного `--start` может быть подана через
`--warmup-ticks`; прогрев только строит индикаторное состояние и не торгует.
Активный профиль предоставленного MT5-отчёта находится в
`parameters/s019-mt5-report-no-news.json`: новости выключены, лимит открытий
изменён пользователем на 3 за серверный день. Остальные поддерживаемые
Inp-параметры сохранены из отчёта. Настройки контракта и запуск описаны в
`parameters/README.md`. Этот профиль не меняет исходные MQL defaults.

## Время отчётов и сверка с журналом

Исходные UTC-метки тиков и исполнений сохраняются. Часовой пояс брокера
используется для границ сигнальных баров, счётчика открытий и пятничного
закрытия. В принятом профиле Europe/Kyiv смещение равно UTC+2 зимой и UTC+3
летом; точный календарь переходов брокера требует отдельного подтверждения.
Часы Windows в Experts и время получения строки дашбордом не подменяют
серверные часы MT5.

Для ордерных прогонов JSON-события содержат `server_time` с явным смещением
и `server_day`. Те же поля экспортируются в `events.csv`; `fills.csv`
дополняется `server_time` и `signal_server_time`. `daily_pnl_server.csv`
группирует изменение equity по серверному дню. Обычный `daily_pnl.csv`
сохраняет UTC-группировку; обе суммы сверяются с изменением итоговой equity.
График показывает часы брокера и UTC во всплывающей подсказке. Эти поля
позволяют сопоставлять одно событие в разных часовых поясах без сдвига
самой котировки или повторного импорта данных.

## Модель исполнения и оставшиеся различия

- Ордерный режим выполняет рыночный запрос на текущей доступной котировке
  после callback, как синхронный запрос EA. Это отличается от прежней модели
  целевого веса с исполнением на следующем тике. Используются только известные
  котировки и завершённые бары; будущие цены не читаются.
- Серверные SL/TP и ранее выставленные лимиты обрабатываются перед OnTick.
  Поэтому GTC-лимит может исполниться на первой котировке нового бара до
  отмены по сроку в EA. Новая лимитная заявка начинает проверяться со следующего
  исходного тика.
- Buy Limit срабатывает по Ask, Sell Limit по Bid. При гэпе допускается
  улучшение цены; проскальзывание не делает исполнение хуже лимита. SL закрывает
  по доступному Bid/Ask, TP — не хуже заданного уровня. Конкретные брокерские
  правила и MT5-режим моделирования могут отличаться.
- Частичное исполнение, реквоты, отказ сервера и stop-out не симулируются.
  `InpDeviationPoints` сохраняется, но не превращается в выдуманное фактическое
  проскальзывание; издержки бэктеста задаются отдельно.
- Задержка входа срабатывает на первом доступном тике после срока. Независимые
  OnTimer между котировками пока не воспроизводятся. Дедлайн использует секунды,
  как MQL datetime. Python PRNG воспроизводим при положительном seed, но его
  последовательность не заявлена идентичной MathRand. При seed=0 выбранное
  случайное зерно сохраняется в отчёт.
- Отображение индикаторов/линий, исходный event-log формат и подключение
  реального счёта не переносились. Бэктест начинает с пустого счёта.

## Что проверено

Проверены ручные расчётные сценарии для обеих сторон: старый уровень сигнала,
новое ADR-окно стопа, лимит, RR, денежный риск и лот; отдельно — wick-only,
SL/TP на правильной стороне котировки, гэпы, округление, задержка, срок заявки,
дневной лимит, порядок разворота, пятничная остановка и запуск CLI с JSON-файлом.
Исходник и его fingerprint сохранены для последующего сравнения.

Эти тесты подтверждают правила Python-модели и соответствие разобранным
формулам исходника. Они не заменяют сравнение сделок с MT5 на одинаковой истории,
спецификации, настройках и внешних зависимостях.
