# Оптимизация S-019 на тиках

Из корня проекта:

```bash
uv run --frozen python scripts/optimize_s019.py \
  --data data/deuidxeur-qdm-20251013-20261013 \
  --params parameters/s019-mt5-report-no-news.json \
  --output results/NEW_OPTIMIZATION \
  --trials 256 --workers 4
```

Каталог результата должен быть новым. Скрипт использует Linux fork для
общего массива исходных котировок; `--workers` ограничивает число процессов.
Дополнительных зависимостей кроме существующего lockfile не нужно.

## Протокол

Фиксированы M20, капитал 100000 USD, риск 1000 USD, три открытия в серверный
день, новости выключены. Стоп-буфер, торговые направления, пятничные правила
и задержка 10–45 секунд остаются из исходного профиля. Поиск не оптимизирует
случайное зерно: 190300 используется на обучении, три заранее заданных зерна
190300/190301/190302 — на валидации и последующей проверке.

Дискретные диапазоны:

| Параметр | Значения |
|---|---|
| ADR periods | 8, 12, 16, 24 |
| Long ADR multiplier | 0.75, 1, 1.25 |
| Short ADR multiplier | 1, 1.5, 2 |
| Limit entry from stop | 0.35, 0.5, 0.65, 0.8 |
| Take profit RR | 1.5, 2, 2.5, 3 |
| Slow EMA | 100, 150, 200 |
| Limit lifetime bars | 1, 3, 6 |

Это 5184 комбинации, но скрипт проводит ограниченный поиск: исходный набор,
его соседи, фиксированная случайная выборка до `--trials`, затем все соседи
шести лучших наборов на обучении. Проверенные комбинации записываются в
trials.jsonl; полного перебора скрипт не заявляет.

Обучение: 01.01–01.07.2026, валидация: 01.07–01.09.2026, последующая
проверка: 01.09–конец CSV. Границы — полночь серверного Europe/Kyiv.
Участки имеют независимые счета; предыдущие котировки используются для
прогрева индикаторов без сделок. Позиции между участками не переносятся.

Цель — recovery factor: изменение equity / максимум из 1000 USD и
максимальной тиковой просадки equity в долларах. Кандидат обучения должен
быть прибыльным и закрыть минимум 30 сделок. Лучшие 24 набора и исходный
профиль проверяются на июле–августе с тремя зернами. Выбор — по медиане
recovery factor, при медиане не менее 10 закрытий и прибыли хотя бы на двух
зернах. Набор сохраняется в winner-lock.json до расчёта сентября–октября.

История ранее рассматривалась в других прогонах. Поэтому календарное
разделение не превращает последние даты в совершенно новую рыночную
выборку. После просмотра последующего участка параметры этого поиска не
перевыбираются. Активный профиль не заменяется автоматически.

## Ускорение и проверка

`backtester.s019_search` использует исходные S019 и OrderBroker. Между
границами M20 он находит на исходных Bid/Ask первый тик пересечения SL/TP,
лимитного входа или первого тика после задержки. Свечи обновляются только
из уже прошедших котировок. Просадка считается по всем исходным тикам
векторно, включая тики между callback. Исполнение не переносится на OHLC.

Ускорение предназначено только для встроенного S019 M20; стратегия использует
текущую котировку и собственные свечи. Это не универсальная замена движка
для произвольного Python-кода. Синтетические сценарии обеих сторон, задержек,
сроков pending и пятничного cutoff сверяются с обычным движком. На реальном
базовом прогоне также сверены все 346 исполнений, итог и максимальная
просадка. Отобранный набор дополнительно проверяется обычным движком.

Ограничения модели сохраняются: QDM и брокерские котировки различаются,
стоимость тика в USD постоянная, свопы и стоп-аут не моделируются, отсутствующие
MT5 include-файлы не восстановлены. Эти условия записаны в protocol.json.
